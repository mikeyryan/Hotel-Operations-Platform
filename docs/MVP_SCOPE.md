# MVP Scope

## Goal

Prove that a small hotel team can submit, assign, update, and complete operational requests in one shared mobile workflow.

## Included

### Accounts and roles

- Sign in
- Staff and manager roles
- Basic user profile with name and department

### Requests

- Create a request
- Add title and description
- Select room or location
- Choose a simple category
- Attach one or more photos
- View request details and timestamps

### Task coordination

- Manager assigns a request
- Assignee views assigned requests
- Statuses: `Open`, `Assigned`, `In progress`, `Completed`, `Cancelled`
- Priority: `Low`, `Normal`, `High`, `Urgent`
- Basic activity history

### Manager view

- List all requests
- Filter by status, category, location, and assignee
- See open and overdue work

## Deliberately postponed

- AI categorization and priority recommendations
- Voice transcription
- Automated escalation
- Advanced dashboards and report export
- Multiple properties and corporate-level analytics
- PMS, housekeeping, or maintenance-system integrations
- Offline synchronization
- Guest-facing features

## MVP acceptance scenario

The MVP is successful when a test user can report a broken light with a photo and room number, a manager can assign it to maintenance, the maintenance user can complete it, and the reporter can see the final status and history.

## Open product decisions

- Which department should be used for the first pilot?
- Can staff see all property requests or only relevant requests?
- Who may change priority or cancel a request?
- What defines “overdue” for each priority?
- How long should photos and activity history be retained?
