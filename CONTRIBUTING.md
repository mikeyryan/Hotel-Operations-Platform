# Contributing

The project is early, so small, documented changes are preferred.

## Before making a change

1. Check the roadmap and MVP scope.
2. Create or link an issue describing the user problem.
3. Keep the change focused on one outcome.
4. Record meaningful product or architecture decisions in the build journey vault.

## Suggested branch names

- `feature/request-form`
- `fix/expo-device-connection`
- `docs/update-roadmap`

## Pull request checklist

- [ ] The change supports the MVP or explains why it is needed now.
- [ ] Relevant screens or behavior were tested.
- [ ] No secrets, real guest data, or employee data were committed.
- [ ] Documentation and screenshots were updated when appropriate.
- [ ] Accessibility and error states were considered.
